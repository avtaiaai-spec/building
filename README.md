# CRM «Космос» — участок + подряд

Интерактивный демонстрационный прототип для сценария покупки участка и предложения строительного подряда. React 19, TypeScript, Tailwind CSS 4, Vite. Сервер, регистрация и ключи API не нужны.

Все объекты, подрядчики и клиент — **тестовые записи**. Отправка предложений имитируется: приложение не отправляет email, SMS или другие сообщения. Офисы — демонстрационные, не список пилотных городов.

## Запуск

Требуется Node.js 22.12+ (проверено на 24.19) и npm.

```sh
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite. Для сборки и проверки готовой версии:

```sh
npm run build
npm run preview
```

## Сценарий демонстрации

1. В выдаче «Загородная» откройте участок 10 сот., ИЖС за 1 850 000 ₽.
2. Нажмите «В подборку». Под фотографией расположен блок «Построить дом на участке» (вариант B).
3. Откройте «Все подрядчики (12)» и нажмите «В подборку» у нужной компании. Откроется выбор её проектов, без автоматического добавления каталога.
4. Задайте площадь дома «От / До» и материал стен, отметьте нужные проекты. Например, у ООО «Строим проекты» фильтр 100–140 м² + «Кирпич» покажет «Горизонт 140».
5. Нажмите «Добавить проекты». Можно выбрать несколько проектов одной или нескольких компаний. Уже добавленные проекты отмечены и недоступны для повторного добавления; кнопка «Проекты (N)» позволяет выбрать дополнительные.
6. Откройте подборку. Здесь риелтор видит связь проекта с компанией с отметкой «только для риелтора». Удалите или добавьте отдельные проекты.
7. Откройте предпросмотр: клиент видит участок и только отмеченные проекты, их площадь, материал, этажность, описание и ориентировочную цену. Названия и аватары компаний скрыты и в предпросмотре, и в итоговом экране отправки.
8. Используйте тестовый контакт `client@example.com` и отправьте предложение. Сохраняются дата, статус, комментарий и независимый снимок выбранных элементов.

Если участок не добавлен, подтверждение появится после выбора проектов. Отмена оставляет выбор проектов в открытом окне, но не меняет подборку. Фильтрация не сбрасывает отмеченные проекты: число скрытых фильтром выбранных вариантов показано внизу.

Одна демонстрационная подборка содержит один участок и несколько проектов. Замена участка требует подтверждения и очищает прежние варианты строительства. Удаление участка сохраняет проекты, но блокирует отправку неполного предложения. Старые подборки с подрядчиками сохраняются и требуют вручную выбрать проекты либо удалить устаревшую запись. Произвольные проекты автоматически не добавляются. Названия компаний также скрыты при просмотре старой истории отправок.

Каталог содержит по шесть тестовых проектов на компанию. Фильтры относятся к площади **дома**, а не участка. Нет автоматического сопоставления проекта с участком, строительного калькулятора, общей сметы или суммирования цены земли и строительства. Цены — демонстрационные значения «от».

Фильтры цены, площади участка, района, типа и операции реально изменяют выдачу объектов. Для Новосибирска представлен другой набор подрядчиков. «Демо: без подрядчиков» демонстрирует пустое состояние.

## Данные и аналитика

Все данные находятся в `src/data.ts`. Единое хранилище подборки и аналитики — `src/store.tsx`. Участок и выбранные проекты хранятся элементами одного массива `items`; проект связан с участком через `plotId`, а с компанией — через `contractorId`. Старый тип `contractor` поддерживается только для явного перевыбора проектов в ранее сохранённых подборках. Новые отправки содержат участок и проекты.

`localStorage`, ключ `kosmos-demo-v1`, сохраняет подборку, имя клиента, офис, последние 500 событий и историю отправок. Интерфейс уведомляет об ошибке записи. Кнопка «Сбросить демо» очищает состояние после подтверждения. Не вводите реальные персональные данные.

Панель «Аналитика пилота» доступна по иконке диаграммы слева. Она показывает только действия в этом браузере, без фиктивных сделок или реальных показателей пилота. Отображаемое время — Екатеринбург, UTC+5; события хранятся в ISO 8601.

## Проверки

```sh
npx playwright install --with-deps chromium
npm test
```

Для уже установленного Chromium:

```sh
CHROMIUM_PATH=/usr/bin/chromium npm test
```

Playwright запускает сервер автоматически. Девять сценариев проверяют выбор нескольких проектов и компаний, комбинацию фильтров и скрытые выбранные варианты, отсутствие названий компаний в клиентских экранах, отмену, дубли, обновление счётчиков, сохранение после перезагрузки, старые подборки, офисы, удаление участка, валидацию контакта, независимость снимка отправки, сброс и планшет.

Для проверки именно production-сборки выполните `npm run build`, затем `TEST_PRODUCTION=1 CHROMIUM_PATH=/usr/bin/chromium npm test`. Проверка запускает отдельный preview на порту 4173 и не использует работающий dev-сервер на 5173. Снимки интерфейса сохраняются в `test-results/`.

## Публикация на GitHub Pages

В репозитории подготовлен `.github/workflows/deploy.yml`: проверка TypeScript, production-сборка, браузерные тесты и публикация статического сайта.

1. Сохраните файлы приложения в GitHub в ветке `main`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Запустите workflow **Deploy Kosmos demo** вручную или новым push в `main`.
4. После успешной публикации ссылка появится в GitHub Actions / Deployments и в настройках Pages.

Vite использует относительный `base`, поэтому сборка поддерживает размещение в подпапке репозитория. Публичный прототип: https://avtaiaai-spec.github.io/building/. Push в `main` запускает повторную сборку, браузерные тесты и публикацию. Публикация приложения на Pages и публикация облачной среды — разные действия.

## Структура

- `src/App.tsx` — связанные экраны CRM, карточка участка, дровер, подборка, предпросмотр, отправка, аналитика.
- `src/ProjectPicker.tsx` — каталог проектов компании, фильтры и явный множественный выбор, общая карточка проекта.
- `src/ui.tsx` — общие диалоги, аватары, пустые состояния и плейсхолдер фотографии.
- `src/styles.css` — компактная CRM-компоновка по предоставленным референсам, адаптация к планшету.
- `tests/scenario.spec.ts` — браузерные проверки сценариев.

Фотографии намеренно заменены плейсхолдерами, как в референсах. Исходный файл `1` сохранён без изменений.
