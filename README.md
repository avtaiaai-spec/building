# CRM «Космос» — участок + подряд

Интерактивный демонстрационный прототип для сценария покупки участка и предложения строительного подряда. React 19, TypeScript, Tailwind CSS 4, Vite. Сервер, регистрация и ключи API не нужны.

Все объекты, подрядчики и клиент — **тестовые записи**. Отправка предложений имитируется: приложение не отправляет email, SMS или другие сообщения. Офисы — демонстрационные, не список пилотных городов.

## Запуск

Требуется Node.js 22.12+ (проверено на 24.19) и npm.

```sh
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite. Для сборки и проверки готовой версии:

```sh
npm run build
npm run preview
```

## Сценарий демонстрации

1. В выдаче «Загородная» откройте участок 10 сот., ИЖС за 1 850 000 ₽.
2. Нажмите «В подборку». Под фотографией расположен блок «Построить дом на участке» (вариант B).
3. Откройте «Все подрядчики (12)», добавьте ООО «Строим проекты» и ГК «Сибирский дом».
4. Откройте подборку. Удалите одного подрядчика и вернитесь через «Выбрать подрядчиков»: состояния кнопок синхронизированы.
5. Добавьте подрядчика снова, откройте предпросмотр, затем отправку.
6. Введите тестовый контакт, например `client@example.com`, и нажмите «Отправить предложение».
7. Успешная отправка сохраняет дату, статус, комментарий и отдельный снимок состава предложения. Изменение текущей подборки не меняет историю.

Если подрядчик выбран раньше участка, появится подтверждение добавления обоих элементов. В этом демонстрационном сценарии одна комплексная подборка содержит один участок и нескольких подрядчиков. Замена участка требует подтверждения и очищает прежних подрядчиков. Удаление участка сохраняет подрядчиков, но блокирует отправку неполного предложения.

Фильтры цены, площади, района, типа и операции реально изменяют выдачу. Для Новосибирска представлен другой набор подрядчиков. «Демо: без подрядчиков» демонстрирует пустое состояние. Технологии строительства — информационные теги, не алгоритм подбора. Конкретные проекты домов, смета и суммарная цена не рассчитываются.

## Данные и аналитика

Все данные находятся в `src/data.ts`. Единое хранилище подборки и аналитики — `src/store.tsx`. Участок и подрядчики хранятся элементами одного массива `items`; подрядчик связан с участком через `plotId`.

`localStorage`, ключ `kosmos-demo-v1`, сохраняет подборку, имя клиента, офис, последние 500 событий и историю отправок. Интерфейс уведомляет об ошибке записи. Кнопка «Сбросить демо» очищает состояние после подтверждения. Не вводите реальные персональные данные.

Панель «Аналитика пилота» доступна по иконке диаграммы слева. Она показывает только действия в этом браузере, без фиктивных сделок или реальных показателей пилота. Отображаемое время — Екатеринбург, UTC+5; события хранятся в ISO 8601.

## Проверки

```sh
npx playwright install --with-deps chromium
npm test
```

Для уже установленного Chromium:

```sh
CHROMIUM_PATH=/usr/bin/chromium npm test
```

Playwright запускает сервер автоматически. Покрыты полный пользовательский сценарий из задания, сохранение после перезагрузки, отмена, детали подрядчика, дубли, фильтры, офисы, раскрытие списка, удаление участка, валидация контакта, независимость снимка отправки, сброс и планшет. Снимки интерфейса сохраняются в `test-results/`.

## Публикация на GitHub Pages

В репозитории подготовлен `.github/workflows/deploy.yml`: проверка TypeScript, production-сборка, браузерные тесты и публикация статического сайта.

1. Сохраните файлы приложения в GitHub в ветке `main`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Запустите workflow **Deploy Kosmos demo** вручную или новым push в `main`.
4. После успешной публикации ссылка появится в GitHub Actions / Deployments и в настройках Pages.

Vite использует относительный `base`, поэтому сборка поддерживает размещение в подпапке репозитория. Приложение пока не опубликовано автоматически из облачной сессии. Публикация приложения на Pages и публикация облачной среды — разные действия.

## Структура

- `src/App.tsx` — связанные экраны CRM, карточка участка, дровер, подборка, предпросмотр, отправка, аналитика.
- `src/ui.tsx` — общие диалоги, аватары, пустые состояния и плейсхолдер фотографии.
- `src/styles.css` — компактная CRM-компоновка по предоставленным референсам, адаптация к планшету.
- `tests/scenario.spec.ts` — браузерные проверки сценариев.

Фотографии намеренно заменены плейсхолдерами, как в референсах. Исходный файл `1` сохранён без изменений.
